    How it decides

    Every domain gets one word

    The script asks the registry for name.ext and sorts the answer into exactly one status. It never rounds a guess up to open.

    The registry for the extension answers

    1. No record

      An RDAP 404 sent as a real RDAP reply, or a WHOIS "not found"

      1. Does that registry report nic.ext or google.ext as registered?

        no unknown the registry failed its sanity check

      2. With a free Vercel token, Vercel is asked whether it sells the name and at what price. Vercel sells domains, so its API can confirm the real price.

        standard price open $11

        well above standard premium

        will not sell it reserved

        no token, or no price came back open* no record, price not verified

    2. A record

      The registry returned this domain's registration

      1. What does the record say?

        redemption or pending delete expiring

        nameservers at a parking or sale service parked

        anything else taken

    3. Anything else

      No reply after five tries, a rate limit, a redirect, an unreadable reply, a bad certificate, an unsupported extension

      1. always unknown never counted as open

    Where the answers come from

    • .com .net Verisign RDAP
    • most others the registry's RDAP server, from IANA's list
    • .io .co .sh .me .so .gg the registry's WHOIS

    Redirects are never followed. Every answer is saved in results.json with the URL or server that gave it and the time.

    FAQ

    Fair questions

    Why is it free?

    Because it costs almost nothing to run. Your own Claude Code writes the names, and the registries answer lookups for free. There is no server doing the work, so there is nothing to charge for. It is MIT licensed, and there is no paid tier coming.

    What data leaves my machine?

    The candidate names go to the domain registries that answer for them, and to Vercel's domain API only if you set a Vercel token (Vercel sells domains, so its API can confirm the real price). Your description stays in your own Claude Code session. The skill has no server and collects nothing. The checker on this page sends the name you type from your browser to Verisign, and nowhere else. This website stores only the email you choose to give below.

    Why not just ask the model if a domain is free?

    A model cannot know. It guesses from what it read in training, and short, sayable .com names get registered every day. Brandrune treats the model as the writer and the registry as the only judge.

    Does it buy domains or earn referral fees?

    No. It reports what the registry said. You register the name you pick, wherever you like. There are no affiliate links.

    Does it check trademarks?

    No. For the names you lean toward, Claude runs a quick web search for the name in your field and points you to the USPTO search. Clearing a trademark is your call.

    Which extensions work?

    .com and .net through Verisign, most others through their registry's RDAP server, and .io, .co, .sh, .me, .so and .gg through WHOIS. Extensions with neither, such as .us and .de, come back unknown, never open. Two-part extensions such as .co.uk are refused before anything is checked.

    Do I need Claude Code?

    For the naming, yes. The checker also runs on its own: python3 brandrune.py verify yourname.com.

    It used to be called weavenames.

    Same project, new name. Existing weavenames installs keep working, and the README has the one-time switch to the new name.
